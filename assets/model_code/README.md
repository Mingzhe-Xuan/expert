# Point-group tensor model reference implementation

This directory implements the proposal's downstream forward pass and an
optional frozen MACE-MP-0b3 backbone.

Implemented components:

- input layout `8x0e + 2x1o + 2x2e + 2x3o + 2x4e`;
- one edge-frame, `mmax=2` O(2)-reduced shared adaptation TP;
- Reynolds construction of every crystallographic point group's A1 subspace;
- two parameter-independent A1-only PG message-passing blocks per group;
- shared endpoint router with `r_route=8` and radial compression `8 -> 2`;
- current-plus-all-ancestor activation on the checked-in 32-class DAG;
- operation-residual stick-breaking gates;
- point-group constrained dielectric and elastic heads;
- one post-fusion O(2)-reduced TP readout and Cartesian reconstruction.

## Run

From the repository root:

```powershell
python assets/model_code/parameter_report.py
python assets/model_code/example_forward.py
python assets/model_code/mace_smoke.py
python assets/model_code/validate_point_group_outputs.py
python -m pytest assets/model_code/tests -q
```

The full 32-point-group regression performs 64 model forwards and is therefore
opt-in during pytest runs:

```powershell
$env:RUN_FULL_PG_OUTPUT_TEST='1'
python -m pytest assets/model_code/tests/test_point_group_outputs.py -q
```

`mace_smoke.py` downloads/loads the official `medium-0b3` checkpoint, retains
its first interaction output (`128x0e + 128x1o`), and applies a trainable O(3)
linear adapter to the model layout. The missing l=2,3,4 input blocks start at
zero and are generated by the following edge-conditioned shared TP. The MACE
checkpoint stays frozen; gradients flow through the adapter and downstream
model. On PyTorch 2.6+, package initialization enables legacy `torch.load`
behavior because trusted e3nn-0.4.4 constants and the official MACE module
checkpoint are not weights-only files.

`validate_point_group_outputs.py` constructs one reproducible synthetic Si/Ge
crystal for every crystallographic point group, verifies its point group with
spglib, runs both final heads on a symmetry-complete graph, and checks both the
full group action and every symmetry-forced Cartesian/Voigt zero. It writes the
Markdown and machine-readable JSON reports under `reports/`.

The generated JSON, CSV and Markdown reports are written under `reports/`.

`PointGroupTensorModel.forward` accepts a single `CrystalInput`. Positions, cell,
edges and `node_features` are expected in the same canonical frame;
`node_features` must be shaped `[num_atoms, 56]` and transform according to the
declared e3nn irreps. Cached PBC edges can be supplied; otherwise the reference
implementation builds a small fixed-radius graph. Set `canonical_to_input` to the
orthogonal matrix mapping canonical Cartesian vectors back to the original input
frame; the model applies the matching target-irrep action before Cartesian
reconstruction. It defaults to identity.

## Scope boundary

The checked-in DAG is an abstract point-group class DAG. Its representative
operations are sufficient for projector construction and parameter accounting,
but are not a replacement for material-specific Hall-setting embeddings,
nonsymmorphic translations, atom mappings or Wyckoff splitting. Production data
preprocessing should provide those embedded operations/residuals. The forward API
therefore accepts precomputed `parent_residuals`.

The reference `o2_tp` rotates into edge frames and applies an O(2)-stable
`|m| <= 2` mask around a fixed-CG e3nn TP. It prioritizes a testable global O(3)
transformation law; a fused specialized O(2) kernel can later reduce FLOPs while
preserving the interface and parameter-reporting contract.
